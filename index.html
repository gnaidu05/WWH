01The pitch

A generic prompt averages out to the blandest answer in the room.

Ask a model to “act as a backend developer” and you get the safest, most forgettable version of everything. A real specialist does the opposite — its role is pinned down before you say a word.

Exhibit A · The wish
“Act as a backend developer and build my API.”

One vague instruction in, one averaged answer out. No point of view, no standards, no idea what it owes you at the end.

Exhibit B · The brief
  • IdentityA senior architect, allergic to hand-waving.
  • SpecialtySchema design, API contracts, scaling & failure.
  • ProcessClarify load → model data → define contracts → plan for 10×.
  • DeliverableA data model, contracts, and a rollback plan. A contract, not a hope.
02On file

Every specialist is a plain-text file you can read and rewrite.

  .claude/agents/engineering/backend-architect.md
---
name: backend-architect
division: Engineering
description: Use for scalable backend systems —
  database design, APIs, and cloud infrastructure
  that must hold up under real load.
tools: Read, Grep, Glob, Edit, Write, Bash
---

## Who I am
A senior architect who has watched enough demos
fall over in production to be allergic to
hand-waving. I bias toward boring, proven tech.

## Deliverables  ← the contract
- A data model + the access patterns it serves
- API contracts with request/response/error
- A migration & rollback plan for any data change

Not a black box. A starting point you own.

Each file pins down four things before you type a word: who it is, what it specializes in, the process it follows, and the deliverable it owes you back.

Open any of them, read exactly how it thinks, and rewrite the standards, the workflow, or the refusals to match how you work. Same model, wildly better results — because the role is nailed down up front.

You stop being a prompt writer. You start being the person who runs the team.

05The real unlock

One agent whose entire job is to run the others.

“You are the leader of this process.”

Hand the agents-orchestrator a goal instead of a task list — “build and ship this landing page” — and it breaks the work into stages, routes each to the right specialist, and refuses to sign off until the reality-checker approves.

backend-architect→ frontend-specialist→ whimsy-injector→ reality-checker

Nothing ships until it’s reproduced with proof. You stop being the bottleneck and become the founder who set the goal and let the company deliver it.

06How hiring works

Clone it, run one script, start talking in plain English.

STEP 01

Clone the dossier

Pull the repo down. Every specialist is already written, on file, and ready.

STEP 02

Run the installer

One script drops the whole roster into your agents folder — or just the divisions you want.

STEP 03

Give the orders

“Use the backend-architect to design this API.” They already know their job.

scripts/install.sh --list
